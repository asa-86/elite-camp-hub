# راه‌اندازی و وضعیت اتصال

## وضعیت فعلی

- رابط عمومی فارسی، صفحهٔ ورود، صفحهٔ ارتباط با ما و نمای آغازین مدیر، معلم و دانش‌آموز در پروژه هستند.
- عملیات داده‌ای فعلی در `VITE_DATA_MODE=demo` و در فضای ذخیره‌سازی مرورگر اجرا می‌شود. این حالت فقط برای بازبینی رابط و گردش‌کار نمونه است؛ نقش‌ها، نشست و محدودیت تلاش ورود در مرورگر قابل دست‌کاری هستند و برای کاربران واقعی امن نیستند.
- migration پایه در `supabase/migrations/202610170001_core_schema.sql` طرح جداول و سیاست‌های RLS را آماده می‌کند. هنوز روی پروژهٔ Supabase اجرا یا با آزمون RLS بررسی نشده است.
- اتصال client، ورود با نام کاربری از طریق Edge Function، ایجاد امن حساب، محدودسازی نرخ سمت سرور و سرویس واقعی فایل هنوز پیاده‌سازی/پیکربندی نشده‌اند. تا آماده‌شدن آن‌ها `VITE_DATA_MODE=demo` را تغییر ندهید.

## اجرای محلی پیش‌نمایش

1. Node.js و npm نصب باشند.
2. وابستگی‌ها را با `npm install` نصب کنید.
3. `.env.example` را به `.env` کپی کنید. برای پیش‌نمایش محلی، `VITE_DATA_MODE=demo` را نگه دارید.
4. `npm run dev` را اجرا کنید.

حساب‌های آزمایشی از پیش در دادهٔ نمونه ساخته می‌شوند:

| نقش | نام کاربری | گذرواژه |
| --- | --- | --- |
| مدیر | `admin` | `Admin@1405` |
| معلم | `teacher` | `Teacher@1405` |
| دانش‌آموز | `student` | `Student@1405` |

این گذرواژه‌ها فقط برای پیش‌نمایش هستند؛ آن‌ها را برای استقرار واقعی استفاده نکنید.

## آماده‌سازی Supabase

1. یک پروژهٔ Supabase بسازید و URL و کلید publishable را در متغیرهای `VITE_*` قرار دهید.
2. migration پایه را بازبینی و با Supabase CLI در محیط توسعه اجرا کنید. پیش از تولید، سیاست‌ها را با حساب‌های واقعی هر نقش آزمایش کنید.
3. Edge Functionهای ورود با نام کاربری و ایجاد حساب را بسازید. کلید `SUPABASE_SERVICE_ROLE_KEY` فقط در secretهای سمت سرور باشد. ساخت کاربر Auth و درج profile باید در یک گردش‌کار کنترل‌شده انجام شوند.
4. `src/services/api.ts` را به client/توابع سرور Supabase متصل کنید؛ `VITE_DATA_MODE` به‌تنهایی اتصال را برقرار نمی‌کند.
5. هاست فایل باید API آپلود و لینک کوتاه‌عمر با کنترل مجوز فراهم کند. `VITE_FILE_SERVICE_URL` فقط نشانی API است؛ فایل‌ها به‌صورت خودکار یا مستقیم به Supabase Storage نمی‌روند.
6. `VITE_SITE_URL` را روی دامنهٔ نهایی قرار دهید تا canonical و Open Graph درست باشند.

## متغیرهای محیطی

`.env.example` فقط نام متغیرها و مقدارهای نمونه دارد. متغیرهای `SUPABASE_SERVICE_ROLE_KEY` و `FILE_SERVICE_API_TOKEN` محرمانه‌اند و باید فقط در secret store هاست/Edge Function نگهداری شوند. هیچ متغیر محرمانه‌ای نباید `VITE_` داشته باشد.

برای مستندکردن فایل‌ها، به `src/services/files.ts` و قرارداد API آن نگاه کنید. حذف رکورد و حذف فایل باید در سرویس سمت سرور با جبران خطا هماهنگ شوند؛ adapter آزمایشی فعلی فایل واقعی را پایدار ذخیره نمی‌کند.
