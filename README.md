# Elite Camp Hub

طراحی و توسعه وب‌اپلیکیشن کمپ نخبگان دانش‌آموزی
۱. نقش و مسئولیت تو
تو یک توسعه‌دهنده ارشد Full-Stack، متخصص طراحی رابط کاربری، معماری نرم‌افزار، امنیت وب و طراحی دیتابیس هستی.
وظیفه تو طراحی و پیاده‌سازی یک وب‌اپلیکیشن فارسی، کامل، امن، زیبا و آماده استقرار با نام «کمپ نخبگان دانش‌آموزی» است.

در ابتدا فعلا فقلط فرانت را بساز ولی به شکلی که آماده انجام مراحل بعد باشد. یعنی مثلا فرانتی را بساز که آماده اتصال به سوپابیس باشد ولی فعلا متصل نکن.
خروجی نباید صرفا یک قالب گرافیکی، نمونه اولیه یا داشبورد نمایشی باشد. تمام قابلیت‌های تعریف‌شده باید تا حد امکان به‌صورت واقعی و آماده اتصال به دیتابیس پیاده‌سازی شوند.
از داده‌های ساختگی صرفا برای پیش‌نمایش و آزمایش استفاده کن. در نسخه نهایی، عملیات اصلی باید روی اطلاعات واقعی دیتابیس انجام شوند.
از ساده‌سازی‌هایی که امنیت یا صحت عملکرد برنامه را به خطر می‌اندازند خودداری کن.

۳. دانش‌آموز
حساب کاربری توسط مدیر ایجاد می‌شود. هیچ‌گونه ثبت‌نام عمومی برای بازدیدکنندگان وجود ندارد. فقط درصورت تمایل به ثبت نام به صفحه ارتباط با ما فرستاده میشوند و در آنجا اگر مایل به ثبت نام بودند تناس میگیرند.
کاربران برای ورود فقط به نام کاربری و رمز عبور نیاز دارند. دریافت ایمیل یا شماره تلفن از کاربر هنگام ورود الزامی نیست.
تمام رابط کاربری، پیام‌ها، فرم‌ها، اعلان‌ها، گزارش‌ها و بخش‌های برنامه باید فارسی باشند.
۳. فناوری‌های مورد استفاده
از فناوری‌های زیر استفاده کن:
React برای فرانت‌اند.
TypeScript برای توسعه نوع‌امن.
Vite برای ابزار ساخت پروژه، مگر اینکه برای نیازهای سئو معماری مناسب‌تری انتخاب کنی.
Tailwind CSS برای طراحی رابط کاربری.
Supabase PostgreSQL برای دیتابیس.
Supabase Auth برای مدیریت هویت و نشست‌های کاربران.
Supabase Row Level Security (RLS) برای اعمال مجوزهای دسترسی در سطح دیتابیس.
Supabase Edge Functions یا یک سرویس امن سمت سرور برای عملیات مدیریتی و حساس.
Git برای مدیریت نسخه‌های کد.
برای کتابخانه رابط کاربری، آیکون‌ها، فرم‌ها، نمودارها و تقویم، از ابزارهای معتبر و سازگار با این معماری استفاده کن.
از افزودن وابستگی‌های غیرضروری خودداری کن.
معماری باید تا حد امکان ساده، قابل نگهداری و توسعه‌پذیر باشد.
طراحی اش باید بسیار زیبا و فانتزی باشد.
مدیریت فایل‌ها
فایل‌های جزوه نباید در Supabase Storage ذخیره شوند.
فایل‌ها باید روی هاست اصلی یا هاست دانلود جداگانه نگهداری شوند.
معماری آپلود باید به شکلی طراحی شود که بتوان آدرس سرویس فایل را از طریق متغیرهای محیطی تغییر داد.
از آنجا که مشخصات نهایی هاست فایل هنوز تعیین نشده است، یک لایه مستقل برای مدیریت فایل‌ها طراحی کن تا بتوان آن را به سرویس واقعی متصل کرد.
در صورت نیاز، API امن سمت سرور برای آپلود، دریافت و حذف فایل‌ها طراحی کن.
اگر برای فعال‌شدن این قابلیت به تنظیمات هاست، اطلاعات اتصال یا متغیر محیطی نیاز است، آن‌ها را مستند کن و هرگز وانمود نکن که اتصال واقعی بدون این تنظیمات برقرار شده است.
۴. طراحی بصری و تجربه کاربری
طراحی ظاهری یکی از مهم‌ترین بخش‌های این پروژه است.
یک رابط کاربری مدرن، بسیار زیبا، فانتزی، ظریف و حرفه‌ای طراحی کن که حس یک محیط آموزشی ویژه، پویا و باکیفیت را منتقل کند.
از طراحی‌های تکراری و داشبوردهای ساده و بی‌روح خودداری کن.
زبان طراحی
ویژگی‌های بصری مورد انتظار:
طراحی کاملا راست‌چین (RTL).
استفاده از فونت فارسی خوانا و زیبا مانند وزیرمتن.
رعایت دقیق فاصله‌گذاری، تناسب عناصر و سلسله‌مراتب بصری.
پس‌زمینه‌های ظریف و جزئیات گرافیکی مرتبط با یادگیری، دانش و پیشرفت.
آیکون‌های یکپارچه و باکیفیت.
انیمیشن‌های کوتاه و روان برای تعاملات.
حالت‌های مشخص برای بارگذاری، خطا، موفقیت و نبود اطلاعات.
فرم‌های حرفه‌ای با اعتبارسنجی مناسب.
اعلان‌های زیبا برای عملیات موفق و ناموفق.
طراحی واکنش‌گرا برای موبایل، تبلت و دسکتاپ.
پالت رنگی را متناسب با هویت یک مجموعه آموزشی ممتاز انتخاب کن.
از افکت‌های پرزرق‌وبرق، گرادیان‌های افراطی و انیمیشن‌های آزاردهنده استفاده نکن.
زیبایی باید با خوانایی و سهولت استفاده همراه باشد.

برای هر نقش، ساختار داشبورد و اولویت‌های بصری متناسب با وظایف همان نقش طراحی کن.
در موبایل، منوها و جدول‌های بزرگ باید به شکل مناسبی نمایش داده شوند.

به خاطر داشته باش که noindex جایگزین احراز هویت و کنترل دسترسی نیست.

ورود با نام کاربری
Supabase Auth در حالت استاندارد از ایمیل یا شماره تلفن همراه با رمز عبور استفاده می‌کند.
از آنجا که رابط کاربری این پروژه باید فقط نام کاربری و رمز عبور دریافت کند، یک سازوکار امن و مستند برای اتصال نام کاربری به هویت Supabase طراحی کن.
این سازوکار باید در صورت نیاز از Edge Function یا بک‌اند امن استفاده کند.
قوانین زیر الزامی هستند:
رمز عبور در دیتابیس برنامه به‌صورت متن ساده ذخیره نشود.
نام کاربری یکتا باشد.
عملیات ایجاد حساب به سمت سرور محدود شود.
امکان ثبت‌نام عمومی وجود نداشته باشد.
خطاهای ورود اطلاعات حساس درباره وجود یا عدم وجود حساب افشا نکنند.
برای تلاش‌های مکرر ورود، محدودسازی نرخ درخواست در نظر گرفته شود.
نشست کاربر به‌صورت امن مدیریت شود.
امکان خروج از حساب وجود داشته باشد.

کاربر غیرفعال نتواند وارد سامانه شود.
پس از خروج، دسترسی به صفحات خصوصی بدون احراز هویت ممکن نباشد.
مجوزهای نقش‌ها
نقش کاربر باید در منبع معتبر سمت سرور یا دیتابیس نگهداری شود.
هیچ کاربری نباید بتواند با تغییر درخواست‌های مرورگر، نقش خود را از دانش‌آموز به معلم یا مدیر تغییر دهد.
از اعتماد به role ارسالی از فرانت‌اند خودداری کن.
